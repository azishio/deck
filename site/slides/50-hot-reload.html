Edit on slide 14, stay on slide 14

A replacement iframe loads in the background. The old one stays on screen until the new one reports deck:ready, then they crossfade.

The current slide id, step, presenter timer and blackout survive. Arbitrary JavaScript state does not — that is a deliberate limit, not an oversight.

Stylesheet edits swap the <link> instead of reloading anything.

What triggers what

  • slide HTML → that iframe only
  • tokens / theme CSS → stylesheet swap, no reload
  • component JS → only frames using those tags
  • add / delete / rename → manifest update, no restart
